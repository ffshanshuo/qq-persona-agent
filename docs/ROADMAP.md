# Roadmap

原则：**每一层都要能被单独测试，也要能自己变好。** 下面的顺序按「对『像真人』的边际收益 × 实现成本」排列。

## 正在做 / 下一步

- [ ] **学习分随时间衰减**。现在被夸过的表情会一直有优势；改成「最近 7 天的反馈权重更高」，避免三个月前的一句「哈哈哈」永久锁死排序。
- [ ] **日记式压缩**。`context.js` 现在的摘要是一条扁平文本；试试按「今天发生的事」组织成 3–5 个事件，巩固时生成，召回时当长时记忆用。
- [ ] **多人群聊的人物建模**。群聊目前只按群建上下文；下一步给「群里每个人」也建轻量 profile（谁爱求助、谁爱开玩笑），插话时用得上。
- [ ] **主动开口的理由要更具体**。现在 `longing.reasonOf()` 给的是「很久没说话 + 关系分」；应该接上「上次聊到你想看海」这种具体钩子。

## 中期

- [ ] **多模型路由策略可学习**。现在固定两个模型抢答；可以按任务类型（短回/长回/看不懂的图）分别记延迟与质量。
- [ ] **情绪与人格的自评闭环**。定期让模型读自己的痕迹，回答「这几轮你觉得自己哪里不像人」，作为 `evolve.js` 的输入之一。
- [ ] **可插拔的收发层**。目标是把 OneBot 收发抽成 `transport/`，让官方 QQ 开放平台、官方机器人、其他 IM 都能复用十几层人格模块。
- [ ] **配置自解释**。`config/*.json` 的 `_note` 已经写了原因，下一步让 `evolve.js` 把「为什么动了这个参数」写进 `config/tuning.json` 的 history，方便回滚。

## 想清楚但不急着做

- [ ] 语音：现在只做 TTS 单向；ASR 需要另找通道（本机没有可用的转写服务）。
- [ ] 图片生成：给「发个自拍/画个图」这类请求做个稳定的生成出口。
- [ ] 向量检索：记忆图现在用 bigram 相似度 + 情感同调，规模上千节点后可能需要真正的 embedding（会引入依赖和外部调用，谨慎）。
- [ ] Web 面板：`node scripts/mind.js graph <key>` 目前是文本；做一个只读的本地页面会更好看，但要小心别把个人数据暴露到局域网。

## 明确不做

- 群发 / 批量加好友 / 营销自动回复 —— 既容易封号，也不是这个项目想研究的东西。
- 「模拟真人到让人无法分辨」的话术 —— 项目默认在被问身份时坦承是 AI。
- 把聊天记录上传到第三方做训练。
